## 0. 한 줄 요약
대화를 **네 종류의 데이터 파일**로 나눈다.
1. 공통 의도 사전: 모든 장면에서 다시 쓰는 "플레이어 말의 뜻" 60개(실제 목록은 `docs/13`, 이 문서는 모양만 정한다) [수정 D3-24]
2. 인물 카드의 기계용 부분
3. 장면 파일: 흐름과 해석표, 대답 후보
4. 언어별 문장 표

게임은 플레이어가 쓴 말을 의도 하나로 바꾼다. 그 의도에 해당하는 해석표 줄을 따라 분기한다. 대답은 조건에 맞는 후보 중 **이번 삶에서 아직 안 한 것**을 고른다.

## 2. 파일 구성 (제안)
```
game/data/
  flags.json                     플래그 장부: 모든 플래그의 이름·종류·범위·설명
  dialogue/intents.json          공통 의도 사전 (뜻·계열만, 문장 없음)
  characters/C-012.json          인물 카드의 기계용 부분
  dialogue/scenes/o01/y22_library.json   장면 하나 = 파일 하나
game/locales/
  ko/intents.json                의도별 대표 문장(매칭 모델이 비교할 예문)
  ko/scenes/o01/y22_library.json 장면 문장 표 { ID: { text, context } }
  en/…, ja/…                     같은 구조
```
- **장면 구조와 문장을 나눈 이유**: 번역가가 장면 흐름을 건드리지 않고 문장 표만 옮길 수 있다. 장면 파일에는 문장 ID만 둔다.
- 문장 표는 지금 `game/data/strings/ko.json`(T-005)과 **같은 모양**(`text` + `context`)이다. 검사기도 같은 것을 쓴다.
- 인물 카드 원본은 그대로 `docs/lore/인물/*.md`(사람이 읽는 글)에 둔다. 게임이 읽는 칸만 JSON으로 옮긴다. 두 곳이 어긋나면 검사기가 경고한다.

## 3. 각 파일의 모양

### 3-1. 플래그 장부 `flags.json`
게임 상태의 모든 이름을 한 곳에 미리 적는다. 장부에 없는 이름이 장면에 나오면 오타로 보고 검사에서 실패시킨다.
```json
{
  "trust": { "type": "int", "scope": "life", "per": "character", "range": [-3, 3], "desc": "인물별 신뢰. 되감기면 0" },
  "PIECE_O01": { "type": "enum", "values": ["없음", "甲만", "乙만", "맞물림"], "scope": "run", "desc": "의심 설계 5절" },
  "knows.성배행": { "type": "bool", "scope": "meta", "desc": "주인공이 알게 된 진실 조각. 되감겨도 남는다" },
  "SURE": { "type": "list", "scope": "life", "desc": "입으로 단정한 것들" },
  "cnt.c004_q": { "type": "int", "scope": "scene", "desc": "C-004 앞에서 한 질문 수" }
}
```
- **범위(scope)가 이 게임의 핵심**이다.
  - `life`: 한 번의 삶. 되감기면 지워진다. NPC의 기억과 관계가 여기 든다.
  - `run`: 한 출신의 세 삶 전체.
  - `meta`: 주인공의 기억. 되감겨도 남는다.
  - `scene` **[수정 D3-5]**: 한 장면 안에서만. 장면이 끝나면 0. 셈판(`cnt.*`)과 `input.empty` 같은 이번 입력 값에 쓴다. 인물 양식 5-4가 "`docs/12`에 없는 범위"라고 요청한 것이다.
- 그래서 "NPC는 기억 못 하는데 주인공은 안다"를 데이터로 쓸 수 있다.
- **이름 짓는 규칙 [수정 D3-12]**: 엔딩·의심 판정에 쓰는 플래그는 **영문 대문자 + `_` + 출신 번호**(`PIECE_O01`, `GODS`). 게임 중에 쌓이는 보조 상태는 **소문자 + 점**(`knows.성배행`, `did.c007_look_direct`, `cnt.c004_q`). 장면 식에서는 `knows('성배행')`처럼 읽기 함수로도 쓸 수 있고, 같은 장부 항목 `knows.성배행`을 가리킨다(3-5).
- **초기 등록 목록 [수정 D3-12]** — 원본 예시는 4개뿐이었다. 의심 설계 v1.1 5절과 엔딩 v3 0-8절에 이미 있는 이름은 처음부터 장부에 올린다.
  | 이름 | 종류 · 범위 | 출처 | 비고 |
  |---|---|---|---|
  | `trust` | int -3~3 · life · 인물별 | 12 3-1 | |
  | `PIECE_Oxx` | enum · ❓ run 추천 | 의심 설계 5 | 배드 분기를 세 삶에 걸쳐 판정하므로 `life`로는 지워진다. plot-architect 확인 |
  | `TRUST_Oxx` | 인물 ID · run | 의심 설계 5 | `trust`와 **대소문자만 다르다**. 오타 위험 → ❓ `TRUSTED_Oxx` 같은 이름으로 바꿀지 스토리팀 확인 |
  | `CERT` | int · run | 의심 설계 5 | 표시값, 판정에 쓰지 않음 |
  | `FAMILY_OK` / `FAMILY_FAIL` | list(출신·장면·계열·상대) · run | 의심 설계 5 | 3-4 `familyResult`가 쓴다 |
  | `SURE` | list · life | 의심 설계 5 | 3-4 `records`·`suspects`가 쓴다. 범위는 ❓ plot-architect 확인 |
  | `FILL_Oxx` | text · life | 의심 설계 5 | O13·O16, 판정에 쓰지 않음 |
  | `C1` `C2` `GODS` `KEY` `V1a` `V1b` `V1c` `TEMPT` `RULE` `KINGS` `COMP` | 종류·범위는 엔딩 조립(T-011)에서 확정 | 엔딩 v3 0-8 | 이름만 먼저 예약한다 |
  | `input.empty` | bool · scene(이번 입력) | 인물 양식 5-2 | 게임 규칙이 켠다 |
  | `did.<인물>_<행동>` | bool · life | 인물 양식 5-3 | 게임 조작이 켠다 |
  | `cnt.<인물>_<무엇>` | int · life 또는 scene | 인물 양식 5-4 | 3-3 `counters`가 센다 |
- **NPC가 들은 말 기록 [수정 D3-17]**: 장면 중 오간 말은 `{ 장면, 의도, 인물 }`로만 남긴다(`said`). 플레이어가 쓴 **글 원문은 저장하지 않는다**(크기·개인 정보). 묶인 사람(명부·계약·서원) 앞에서 한 것은 `heard` 목록에 따로 올라가 대악마 꿈 장면이 읽는다(R10).

### 3-2. 공통 의도 사전 `dialogue/intents.json`
```json
{
  "families": ["믿는다", "따진다", "떠본다", "숨긴다"],
  "intents": [
    { "id": "truth",    "family": "믿는다", "desc": "본 것·아는 것을 그대로 말함" },
    { "id": "lie",      "family": "숨긴다", "desc": "알면서 사실과 다르게 말함" },
    { "id": "deflect",  "family": "숨긴다", "desc": "얼버무림, 화제 돌리기" },
    { "id": "threaten", "family": "따진다", "desc": "해를 끼치겠다고 겁줌" },
    { "id": "bargain",  "family": "떠본다", "desc": "대가를 요구하거나 거래를 제안" },
    { "id": "ask_back", "family": "떠본다", "desc": "질문으로 되받기" },
    { "id": "accuse",   "family": "따진다", "desc": "상대를 단정해 몰아붙임", "records": "SURE" },
    { "id": "greet",    "family": "믿는다", "desc": "인사", "stance": false },
    { "id": "appeal_faith", "family": "믿는다", "desc": "신·경전·맹세에 기댐", "star": true }
  ],
  "groups": { "question": ["ask_who", "ask_what", "ask_why", "ask_where_when"], "compliment": ["flatter", "praise"] },
  "aliases": { "rank": "invoke_rank", "help_request": "ask_help", "question": "group:question" }
}
```
- **`families`** 고정 목록을 앞에 둔다. 장면 해석표의 계열 이름이 여기 없으면 오타로 실패시킨다.
- **`stance: false`** [수정 D3-1]: 일상 의도(인사·감사·농담·작별). `FAMILY_OK/FAIL` 기록에서 뺀다. 적지 않으면 `true`.
- **`records: "SURE"`** [수정 D3-11]: 이 의도가 맞으면 `SURE`에 기록한다. 내용(누구를 단정했는가)은 3-4 `suspects`로 얻는다.
- **`star: true`**: 중요 장면 전용(★). `common50`은 ★ 없는 의도, `common60`은 전부다.
- **`groups`**: 묶음. 인물 카드의 `question`＊·"진실 거부 계열" 같은 말을 풀 때 쓴다. 장면 식에서 `group:question`으로 쓴다.
- **`aliases`** [수정 D3-8]: 인물 카드에 후보 이름(＊)으로 적힌 것을 공통 id로 잇는다. 카드를 고치는 동안 검사기가 별칭을 풀어서 읽는다. 전체 표는 `docs/13` 8절.
- 예문(매칭 모델이 비교하는 대표 문장 수십 개)은 언어마다 `locales/<언어>/intents.json`에 둔다.
- 60개 목록은 **`docs/13`(수정안)에 있다**. 여기서는 모양만 정한다. [수정 D3-24]

### 3-3. 인물 카드 기계용 부분 `characters/C-012.json`
```json
{
  "id": "C-012",
  "binding": "명부",
  "voice": ["짧은 문장", "존대→반말 전환 빠름"],
  "neverSay": [{ "words": ["옛 신이 옳았다"], "until": "life == 3" }],
  "confusablePairs": [["pity", "insult"]],
  "familyBias": { "믿는다": "의심", "따진다": "굴복", "떠본다": "역이용", "숨긴다": "눈치챔" },
  "unclearLine": "char.c012.unclear",
  "counters": [{ "name": "cnt.c012_q", "counts": ["group:question", "ask_back"], "scope": "scene" }],
  "doc": "docs/lore/인물/C-012_….md"
}
```
- `binding`이 `없음`이 아니면 엔진이 그 장면에서 오간 말을 "대악마가 들은 것" 기록에 남긴다(R10).
- **`neverSay`** [수정 D3-10]: 원본은 `neverIntents`였는데 예시값(`flatter_back`)이 사전에 없는 이름이었고, 인물 카드 11절의 "절대 하지 않는 말"은 **NPC가 하지 않는 문구·낱말**이었다(예: "옛 신이 옳았다", 진짜 이름). 플레이어의 의도가 아니므로 이름을 바로잡았다. 검사기가 그 인물의 **모든 문장 표**에서 이 낱말을 찾아 오류로 잡는다. 의도로 쓸 수 있는 금지(예: 위협을 하지 않는다)는 `neverIntents`를 따로 두되 값은 사전 id만 쓴다. 인물 양식 5-6 표의 칸 이름도 이에 맞춰 고친다(스토리팀).
- **`confusablePairs`**: 이 인물에게 두 의도가 같은 반응을 낳는 짝. 검사기가 **두 의도의 첫 반응 문장 ID가 겹치면 오류**로 잡는다(카드마다 "반응 문장은 다르게"라고 적었다) [수정 D3-15].
- **`familyBias`**: 작가 참고용 한 낱말이다. 엔진은 읽지 않는다. [수정 D3-13]
- **`unclearLine`** [수정 D3-16]: 되묻는 말의 문장 ID. 인물 양식 11절 "확신이 낮을 때의 기본 반응"에서 가져온다.
- **`counters`** [수정 D3-5]: 셈판 자동 증가. "질문은 한 번만", "따지는 말 세 번" 같은 인물 카드의 `cnt.*`를 장면마다 효과를 쓰지 않고 **인물이 한 번에 정의**한다. `counts`에는 의도 id, `group:`, `family:따진다`를 쓸 수 있다.

### 3-4. 장면 파일 `dialogue/scenes/<출신>/<장면>.json` (핵심)
예시는 우리가 지어낸 일반 장면이다(마을 장로가 "어젯밤 무엇을 보았나?" 묻기, docs/08 1절). [수정 D3-13] 인물 ID는 출신별 범위(O01 → C-110~119, 인물 양식 4절)로 고쳤다.
```json
{
  "id": "scene.o01.y03_elder",
  "tier": "normal",
  "when": "life >= 1 && era == '유년'",
  "cast": ["C-111"],
  "start": "q1",
  "suspects": [],
  "localIntents": [
    { "id": "scene:name_son", "family": "믿는다", "desc": "장로의 아들 이름을 대기" }
  ],
  "nodes": {
    "q1": {
      "decision": false,
      "say": [
        { "line": "scene.o01.y03_elder.c111_01", "when": "trust(C-111) <= 0" },
        { "line": "scene.o01.y03_elder.c111_02", "when": "trust(C-111) > 0" },
        { "line": "scene.o01.y03_elder.c111_03", "when": "knows('장로의아들')", "repeatAcrossLives": true }
      ],
      "ask": {
        "intents": "common50 + scene:name_son",
        "empty": { "go": "r_wary" },
        "byFamily": {
          "믿는다": { "go": "r_open",  "do": ["trust(C-111) += 1"] },
          "따진다": { "go": "r_close", "do": ["trust(C-111) -= 1"] },
          "떠본다": { "go": "r_wary" },
          "숨긴다": { "go": "r_wary",  "do": ["trust(C-111) -= 1"] }
        },
        "byIntent": {
          "bargain":        { "go": "r_coin" },
          "scene:name_son": { "go": "r_son", "do": ["set PIECE_O01 = '甲만'"], "when": "knows('장로의아들')" }
        },
        "resolve": [
          { "when": "intent == 'truth' && !has('우물가목격')", "as": "lie" }
        ],
        "unclear": { "say": ["scene.o01.y03_elder.c111_q1_again"], "then": { "family": "숨긴다" } },
        "familyReplies": {
          "믿는다": ["scene.o01.y03_elder.c111_fr_open"],
          "따진다": ["scene.o01.y03_elder.c111_fr_hard"],
          "떠본다": ["scene.o01.y03_elder.c111_fr_probe"],
          "숨긴다": ["scene.o01.y03_elder.c111_fr_hide"]
        },
        "replies": {
          "truth":    ["scene.o01.y03_elder.c111_rt_01", "scene.o01.y03_elder.c111_rt_02"],
          "lie":      ["scene.o01.y03_elder.c111_rl_01"],
          "threaten": ["scene.o01.y03_elder.c111_rth_01", "scene.o01.y03_elder.c111_rth_02"]
        },
        "familyResult": { "믿는다": "OK", "따진다": "FAIL", "떠본다": "FAIL", "숨긴다": "FAIL", "partner": "증인" }
      }
    },
    "r_open":  { "say": [{ "line": "scene.o01.y03_elder.c111_10" }], "go": "end" },
    "r_coin":  { "say": [{ "line": "scene.o01.y03_elder.c111_20" }], "go": "end" },
    "end":     { "end": true }
  }
}
```
읽는 법:
- **`byFamily`가 기본 규칙**이고 `byIntent`가 예외다. docs/08의 "기본 규칙 + 예외"와 같다.
  - 의도 60개를 일일이 연결하지 않아도 4줄로 모든 의도가 어딘가로 간다.
  - 덕분에 작가는 꼭 다르게 가야 하는 의도만 따로 쓴다.
  - **[수정 D3-3] 합침 규칙**: `byIntent` 줄이 있으면 그 의도에 한해 **`byFamily`를 통째로 대신한다**(`go`와 `do` 모두). 계열 효과도 함께 받고 싶으면 그 줄에 `"inherit": true`를 쓴다(`do`가 합쳐진다). 원본은 이 규칙이 없어 `trust` 증감이 두 번 적용되는지 알 수 없었다.
- **`replies`는 분기와 따로** 의도마다 NPC의 첫 반응 문장 후보를 둔다. 같은 분기로 가도 반응 문장은 의도마다 다르다(디렉터 결정 11-13).
  - **[수정 D3-3] 비어 있는 의도는 `familyReplies`(계열 기본 반응)를 쓴다.** 원본에는 "계열 기본 반응 문장을 쓴다"고만 적었고 그 문장을 적을 칸이 없었다. 둘 다 없으면 그 인물의 "말 없음" 반응(침묵·몸짓)이다.
  - **허용 밖 의도 [수정 D3-3]**: 장면의 `intents`에 없는 의도(예: 일반 장면에서 ★ 의도)가 1등으로 맞으면 **그 의도의 계열**을 `byFamily`에서 찾고 반응은 `familyReplies`를 쓴다. 원본은 "허용한 의도만 남김"이라서 고백이 사실대로 말함(truth)으로 슬쩍 바뀌는 문제가 있었다.
- **[수정 D3-4] `localIntents`**: 장면 전용 의도는 여기서 선언한다. 이름은 **`scene:`으로 시작**(인물 양식 5-2)하고 **계열을 반드시 적는다**. 계열이 없으면 `byFamily`를 못 타서 갈 곳이 사라진다. 예문은 `locales/<언어>/scenes/…`에 장면 단위로 둔다.
- **[수정 D3-7] `resolve`**: 모델이 고른 의도를 **게임 상태로 고쳐 읽는** 줄이다(`docs/13` 5절 2번). 위 예: 주인공이 우물가를 본 적이 없는데 "우물가에 있었소"라 했으면 `truth`가 아니라 `lie`로 읽는다. **장면이 쓴 줄만 적용**하고 기본값은 없다. 순서는 4절 흐름 참고.
- **[수정 D3-9] `empty`**: 아무것도 안 쓰거나 "…"만 쓴 입력(`input.empty`)이 가는 곳. 이 칸이 없으면 `silence`와 같은 방법으로(계열 `숨긴다`) 처리한다.
- **[수정 D3-6] `decision`·`familyResult`**: 의심 설계 4계열 표에 오른 **결정 장면만** `decision: true`로 두고 `familyResult`에 4계열 각각의 결과(`OK`/`FAIL`/`중립`)와 상대 종류(`partner`: 동료·증인·무리·적)를 적는다. 엔진은 **`stance`가 켜진 의도**가 이 노드에서 나온 경우에만 `FAMILY_OK/FAIL`에 `(출신, 장면, 계열, 상대, 결과)`를 남긴다. 일상 의도(인사 등)는 남기지 않는다. 일반 장면은 `decision: false`(적지 않으면 같음)다.
- **[수정 D3-11] `suspects`**: 입으로 단정하는 장면(범인 지목 등)에서 후보 이름을 적는다: `[{ "id": "miller", "names": ["방앗간 주인", "방앗간"] }]`. 의도가 `records: "SURE"`(`accuse`)로 맞으면 엔진이 입력 글에서 후보 이름을 **글자 일치**로 찾아 `add SURE '범인=miller'`를 쓴다. 이름을 못 찾으면 되묻는다("누구를 말하는 거요?"). 모델이 사람 이름까지 가르게 하지 않는다. 후보별 장면 전용 의도로 하는 방법도 있다(8절 질문 개발팀 확인 ①).
- **[수정 D3-5] `once`·`allowRepeat`**: `"once": true`인 노드는 한 삶에 한 번만 방문된다(원본 5절이 `once`를 말했지만 정의가 없었다). 일부러 되풀이하는 줄은 `{ "line": "…", "allowRepeat": { "max": 2, "why": "거짓말할 때만 되풀이" } }`(인물 양식 5-5)로 적는다. 이 표시가 없으면 반복 금지 검사가 오류로 잡는다. 반복 금지의 **세 삶 반복 대사**는 `repeatAcrossLives`다.
- 대답 고르기 순서:
  1. `when`이 맞는 후보만 남긴다.
  2. 이번 삶에서 이미 한 줄은 뺀다. 단 `repeatAcrossLives`는 세 삶 반복 대사라서 삶마다 한 번 허용한다. `allowRepeat`는 `max`번까지 허용한다.
  3. 남은 것 중 가장 구체적인 조건을 가진 줄을 고른다. 같은 구체성이면 **장면 파일에 먼저 적힌 줄**을 고른다 [수정 D3-3: 원본은 동점일 때 규칙이 없었다].
  4. 아무것도 안 남으면 그 인물의 "말 없음" 반응(침묵·몸짓)을 쓴다.
- `"말 고르기"` 선택지는 따로 쓰지 않는다. 각 의도의 **대표 문장 1개**를 그대로 버튼 글로 쓴다. 그래서 모델 없이도 같은 해석표로 진행된다(요구 8). **[수정 D3-3]** 허용 밖 의도(★)의 버튼은 일반 장면에서 보이지 않는다.
- **NPC가 이전 삶을 기억하는가 [수정 D3-3]**: `meta` 플래그로 대답 후보를 바꿀 때, 바뀌는 것은 "주인공이 아는 것"에 대한 반응이다. NPC 자신이 기억하는 것으로 말하면 안 된다(NPC는 되감기로 잊는다). 인물 양식 6절에 이 규칙을 한 줄 더한다(스토리팀).

### 3-5. 조건·효과 식 (작은 규칙 언어) [수정 D3-2]
- 형식: `trust(C-111) > 0 && knows('장로의아들') && life == 2` 같은 **짧은 글자 식**. 엔딩 표기(`GODS≥7`, `KINGS=0`)와 비슷하게 읽힌다.
- 쓸 수 있는 것은 **플래그 장부의 이름, 아래 "읽기 함수"·"변수", 비교, `&&`·`||`·`!`, 숫자·문자열**뿐이다.
- 원본은 "함수 호출은 없다"고 썼지만 예시가 `trust(C-031)`·`knows(…)`를 썼다. **정해 둔 읽기 함수만 허용**으로 고친다. 새 함수를 만들거나 반복·정의는 없다. 그래서 검사기가 모든 식을 미리 해석해 오타·없는 플래그·범위 밖 값을 잡을 수 있다.
  | 읽기 함수 | 뜻 | 장부에서 |
  |---|---|---|
  | `trust(C-xxx)` | 그 인물의 신뢰(-3~3) | `trust` |
  | `knows('키')` | 주인공이 아는 진실 조각 | `knows.키` |
  | `has('키')` | 주인공이 가진 물건·정보 (`resolve`에서 사용) | `has.키` |
  | `said('의도', C-xxx)` | 이번 삶에 그 인물 앞에서 그 의도를 한 적 있음 [수정 D3-17] | 들은 말 기록 |
  | `heard('의도')` | 묶인 사람 앞에서 그 의도를 한 적 있음(대악마가 들은 것) | `heard` 목록 |
  | `cnt.이름` `did.이름` | 셈판, 행동 태그(함수 아니라 이름 그대로) | 장부 |
  | 변수 | 뜻 |
  |---|---|
  | `life` | 지금이 몇 번째 삶인가(1~3). 장부의 `scope: life`와 이름이 같지만 다른 것이다 |
  | `year` | 이야기 속 몇 년차인가(인물 양식의 `year >= 12`) |
  | `era` | 시대 낱말(`'유년'` `'청년'` `'장년'` …). 값 목록은 장부 enum으로 고정한다 |
  | `intent` `family` | 이번 입력으로 맞춘 의도·계열 (`resolve`와 `when`에서만) |
  | `input.empty` | 이번 입력이 비었는가 |
- 효과: `set X = v`, `trust(C) += n`, `cnt.x += n`, `add SURE '범인=○○'`, `goto 장면ID`. 인물 양식 5절이 요청한 `cnt.c013_ask += 1` 모양을 받는다 [수정 D3-5].
- 장면 전용 의도 이름은 항상 `scene:` 접두어를 쓴다(예: `scene:name_son`). 예전 예시의 `name_son`은 접두어가 없었다 [수정 D3-4].
- **행동 태그** `did.*`는 말이 아닌 행동(정면으로 보기, 물건 살피기)을 켠다 [수정 D3-5]. 의심 설계 0절 9번 "같은 진실을 말하지 않고 행동으로 옮기면 처벌하지 않는다"가 이것으로 표현된다. 식에서는 `did.c007_look_direct`처럼 이름 그대로 쓴다.

### 3-6. 문장 표 `locales/ko/scenes/…json`
```json
{
  "scene.o01.y03_elder.c111_01": {
    "text": "어젯밤… 네 녀석, 우물가에 있었지.",
    "context": "장로→주인공(아이) · 신뢰 낮음 · 의심 · 복선 아님 · 짧게 끊는 말투"
  }
}
```
ID 규칙은 인물 양식 139줄의 `scene.<출신>.<장면>.<인물>_<번호>`를 따른다. 맨 뒤 번호 대신 `rt_01`(첫 반응 · truth), `fr_open`(계열 기본), `q1_again`(되묻기)처럼 **뜻이 보이는 꼬리**를 쓸 수 있다. 한 장면 안에서 꼬리가 겹치지 않으면 된다 [수정 D3-13].

## 4. 실행 흐름 (게임 안에서) [수정 D3-3·6·7·9·16·17]
```
플레이어 입력
 → (a) 아무것도 안 쓴 입력, "…"만, 기호·숫자만 → input.empty (모델을 거치지 않음) → 장면의 empty 줄 → 6단계로
 → (b) 아주 짧은 입력(네·응·아니…)은 작은 사전 규칙으로 먼저 읽는다(docs/13 5절 4)
 → (c) (기기 안 매칭 모델) 의도별 점수
 → (d) 1등 점수가 기준(threshold) 미만? → unclear(되묻기). 같은 노드에서 두 번째면 then(기본 반응)
 → (e) resolve 줄로 의도를 게임 상태에 맞게 고쳐 읽기 (겉말·속뜻)
 → (f) 1등이 이 장면의 intents 밖이면 그 의도의 계열을 쓴다 (byIntent는 건너뛰고 byFamily + familyReplies)
 → (g) byIntent 있으면 그쪽, 없으면 byFamily → 효과 적용 (합침 규칙은 3-4)
 → (h) replies → 없으면 familyReplies → 없으면 말 없음 반응 → 다음 노드
 → (i) 기록: decision 노드이고 stance 의도면 FAMILY_OK/FAIL · records가 SURE이면 SURE
        · 묶인 사람이 있으면 heard · 모든 입력은 said(의도, 인물)
```
- **기준값(threshold)** [수정 D3-16]: 기본값은 게임 전체에 하나(정확도 시험 T-108에서 정함). 장면이 `"threshold": 0.4`처럼 올리거나 내릴 수 있다. 원본은 "기준 미만"만 있고 기준이 어디서 오는지 없었다.
- **두 번째 되묻기** [수정 D3-16]: 노드를 한 번 방문하는 동안 `unclear`가 몇 번 났는지 엔진이 센다(`scene` 범위, 자동). `then`은 `{ "go": "노드" }` 또는 `{ "family": "숨긴다" }`(그 계열로 읽기)다. 원본의 `"default:r_wary"` 같은 글자 안 약속은 없앴다. `unclear.say`가 비면 인물 카드 `unclearLine`을 쓴다.
- 판정 숫자(신뢰, 플래그)는 **게임 규칙**이 바꾼다. 문장을 고르는 일만 데이터가 한다. AI 실시간 대답을 나중에 붙여도 규칙은 그대로다(docs/08 1절).

## 5. 검사기로 잡을 것 (T-008과 연결)
| 검사 | 실패 예 |

## 7. 크기 어림 (확인 전 추정) [수정 D3-14]
- **원본 어림**: 장면 1개(의도 50~60개, 대답 1~2개씩, 문장 평균 40자)는 한 언어에 약 4~8KB, 장면 3,000개면 12~24MB.
- **검토 계산**: 문장 하나를 `ID 약 45바이트 + text 40자(한글 3바이트 × 40 = 120) + context 약 60자(180) + JSON 기호 약 30 = 약 375바이트`로 잡는다. 장면 하나의 문장은 `replies` 55개 × 1.5개 + 계열 기본 4개 + 노드 말 5~10개 = **약 80~100문장**이다. 그러면 **장면 하나 약 30~40KB**다. 원본 어림은 한글이 3바이트라는 점과 맥락 메모(문장마다 필수)를 빼서 **4~8배 작았다**.
- 장면 3,000개면 한 언어 약 **90~120MB**(압축하면 약 25~35MB), **문장은 약 24만~30만 개**다. 구역 단위로 나눠 불러오면(docs/03 3장 3) 한 번에 받는 양은 작다. 언어가 셋이면 번역 문장이 70만~90만 개라 번역·검수 비용이 큰 숫자다 — 8절 새 결정 ①의 이유다.
- 이 계산도 **확인 전 추정**이다. 장면 하나를 실제로 써서 재면(8절 4번) 바로 맞출 수 있다.
