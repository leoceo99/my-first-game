# 07. 팀 운영 상세

> 디렉터 요청: "스토리 작가는 몇 명인지, 디자이너는 어떤 성향인지, 서로 어떻게 공유하는지"까지 구체적으로.
> 팀원은 모두 AI 에이전트이며, 각자 **다른 성격과 가치관**을 갖도록 설계해 서로 견제하게 합니다.
> 한 명을 부를 때마다 사용량(토큰)이 들기 때문에, 모두가 매번 일하지 않고 **작업마다 필요한 사람만** 투입합니다.

## 1. 조직도 (총 13명)

```
디렉터 (사용자)
  └─ 자비스 (총괄 PD)
       ├─ 스토리팀 (5)
       │    메인 작가 · 플롯 설계자 · 인물·대사 작가 · 설정 관리자 · 비평가
       ├─ 디자인팀 (3)
       │    시스템 디자이너 · 경험 디자이너 · 플레이어 대변인
       ├─ 개발팀 (2)
       │    프로그래머 · QA 테스터
       └─ 아트·현지화 (2)
            아트·사운드 디렉터 · 현지화 담당
```

## 2. 스토리팀 — 5명

"어지간한 영화나 드라마보다 짜임새 있게"를 위해 **쓰는 사람, 구조를 짜는 사람, 지키는 사람, 공격하는 사람**을 나눴습니다.

| 이름 | 파일 | 성향 | 책임 |
|---|---|---|---|
| 메인 작가 | `story-writer` | 감정과 주제를 중시하는 작가. 장면의 힘을 믿음 | 진실·메인 줄거리, 주제, 최종 문장 결정권 |
| 플롯 설계자 | `plot-architect` | 퍼즐 설계자. 모든 사건을 표와 그래프로 생각 | 사건 연표, 출신 100개의 교차점, 복선 장부, 엔딩 조건 설계 |
| 인물·대사 작가 | `dialogue-writer` | 배우처럼 인물에 몰입. 말투와 버릇에 집착 | NPC 인물 카드(욕망·비밀·거짓말·말투), 대사, AI 대화용 인물 설정 |
| 설정 관리자 | `lore-keeper` | 기록 담당. 꼼꼼하고 보수적이며 모순을 싫어함 | 설정집 관리, 연표·인물 상태 모순 검사, 용어 통일 |
| 비평가 | `story-critic` | 냉정한 시청자. 칭찬보다 구멍 찾기가 일 | 개연성·동기·클리셰·반전의 공정성 평가, 점수와 수정 요구 |

**스토리 품질 기준 (비평가 채점표)**
1. 인물이 그 순간 그렇게 행동한 이유가 설명되는가 (동기)
2. 반전 전에 복선이 공정하게 깔렸는가 (다시 보면 보이는가)
3. 우연에 기대는 전개가 없는가
4. 같은 사건이 다른 출신의 시선에서 다르게 보이는가
5. 진부한 전개(클리셰)를 비틀었는가
6. 감정의 고저가 있는가

10점 만점 중 7점 미만이면 되돌려 보냅니다.

## 3. 디자인팀 — 3명

| 이름 | 파일 | 성향 | 책임 |
|---|---|---|---|
| 시스템 디자이너 | `game-designer` | 수학과 규칙을 좋아하는 설계자 | 전투·경제·성장·관계 규칙과 수치, 데이터 구조 |
| 경험 디자이너 | `experience-designer` | 플레이어의 감정을 먼저 생각하는 연출가 | 감정 곡선, 튜토리얼 흐름, 연출, 화면·조작 경험 |
| 플레이어 대변인 | `player-advocate` | 두 개의 인격으로 반대 의견을 내는 역할 | ① 하드코어 전략가(너무 쉽다, 최적해가 하나뿐이다) ② 처음 해 보는 초보(뭘 해야 할지 모르겠다)의 시선으로 모든 설계를 검증 |

## 5. 정보 공유 방식

| 무엇 | 어디에 | 규칙 |
|---|---|---|
| 정답(확정된 설계) | `docs/`, `docs/lore/` | 확정된 것만. 바꿀 때는 결정 기록 남김 |
| 결정 기록 | `docs/decisions/` | 무엇을, 왜, 어떤 대안을 버렸는지 |
| 할 일 | `jarvis/TASKS.md` | 담당자와 **검토자**를 반드시 함께 지정 |
| 인수인계 | `jarvis/handoff/작업ID.md` | 작업 끝에 "다음 사람이 알아야 할 것" 작성 |
| 복선 장부 | `docs/lore/복선장부.md` | 복선 ID, 심은 곳, 회수할 곳, 볼 수 있는 출신 |
| 회의록 | `jarvis/meetings/날짜_주제.md` | 의견이 갈린 안건과 자비스의 정리, 디렉터에게 올릴 선택지 |
| 작업 보고 | `jarvis/reports/날짜.md` | 디렉터용 요약 |

## 6. 작업 흐름 (예: 서브 스토리 하나 만들기)

```
1. 자비스: 작업 지시 (목표, 관련 문서, 완료 기준, 검토자)
2. 플롯 설계자: 사건 구조와 복선 위치 설계 → 인수인계 노트
3. 메인 작가 + 인물·대사 작가: 장면과 대사 작성
4. 설정 관리자: 설정·연표 모순 검사
5. 비평가: 채점 (7점 미만이면 2번이나 3번으로 되돌림)
6. 자비스: 최종 검수 → 데이터 파일 반영 → QA 분기 검사
7. 디렉터: 방향이 바뀌는 내용만 승인 요청
```

## 7. 회의 방식
- 의견이 갈리는 안건(예: 마법 체계의 대가)은 자비스가 관련 팀원 2~3명에게 **각자 따로** 의견을 받습니다. 서로 영향을 받지 않게 하기 위해서입니다.
- 자비스는 의견을 표로 정리하고 추천안을 붙여 디렉터에게 올립니다.
- 디렉터의 결정은 결정 기록으로 남기고 모든 팀원이 따릅니다.

## 8. 사용량(토큰) 관리
- 작은 수정은 자비스 혼자 처리합니다.
- 비평가와 플레이어 대변인은 중요한 결과물에만 투입합니다.
- 회의는 안건당 최대 3명까지 참여합니다.
- 야간 작업은 하루 한 작업으로 제한합니다.
