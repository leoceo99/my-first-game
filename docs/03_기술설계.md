# 03. 기술 설계

> 상태: **초안 v0.1** — 0단계 기술 검증에서 실제로 돌려 보고 확정합니다.
> 중요한 기술 결정은 `docs/decisions/` 에 결정 기록(ADR)으로 남깁니다.

## 1. 핵심 결정: 웹 기반 3D 엔진

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **Three.js + TypeScript (웹)** | 노트북·아이패드 브라우저에서 바로 실행, 링크 하나로 테스트, AI가 직접 실행·검증 가능, 앱 포장 가능 | 대작 엔진보다 그래픽 한계, 도구를 직접 만들어야 함 | **채택** |
| Unity | 자료 많음, 그래픽 좋음 | 이 작업 환경에서 실행·검증 불가 → 매번 사용자가 직접 확인해야 함 | 보류 |
| Unreal | 최고 그래픽 | 무겁고 일반 노트북에서 버거움, 검증 불가 | 제외 |
| Godot | 무료, 웹 출력 가능 | 웹 출력 품질·속도 제약, 검증 도구 부족 | 예비안 |

> 판단 근거: "실무는 전부 AI 담당" + "일반 노트북에서도 동작" + "링크로 바로 테스트".

## 2. 기술 스택 (초안)

| 영역 | 선택 | 비고 |
|---|---|---|
| 언어 | TypeScript | 대규모 코드의 안정성 |
| 빌드 | Vite | 빠른 개발 서버, 웹 배포 |
| 3D 렌더링 | Three.js | 셀 셰이딩(툰 렌더링), 그림자, 후처리 |
| 물리 | Rapier (WASM) | 충돌, 캐릭터 이동, 래그돌 |
| 캐릭터·애니메이션 | glTF 모델 + 애니메이션 리타깃 | 무료 에셋(CC0) + Mixamo 동작 |
| 대화·분기 | 자체 대화 스크립트 형식 (JSON/YAML, 문장마다 ID) | 다국어·분기 추적·엔딩 조건 검사에 유리. ink 도입은 0단계에서 비교 |
| 저장 | IndexedDB + 파일 내보내기 | 여러 저장 슬롯, 버전 관리 |
| 다국어 | 문장 ID + 번역 표 + **맥락 메모**(말투·관계·감정) | 07 현지화 원칙 참고 |
| 테스트 | Vitest(로직) + Playwright(실제 화면 자동 플레이) | 자비스가 밤마다 실행 |
| 배포(테스트용) | claude.ai 아티팩트 링크 → 채팅에서 클릭 한 번으로 실행 | GitHub를 몰라도 됨 |
| 정식 출시 | 웹 → 앱 포장(Capacitor 계열) → 앱스토어 | 맥·개발자 계정 필요 (후반) |
| 멀티플레이 | 처음부터 "게임 상태와 화면 분리" 구조로 설계 | 서버는 후반 단계 |

## 3. 구조 원칙
1. **데이터 중심**: 출신, 아이템, 대사, 퀘스트, 엔딩 조건은 코드가 아니라 데이터 파일로 관리 → 스토리 작가 에이전트가 코드 없이 콘텐츠 추가
2. **시뮬레이션과 화면 분리**: 세계 상태(시간·경제·관계)는 화면 없이도 돌아감 → 자동 테스트, 멀티플레이 대비
3. **구역 단위 로딩**: 오픈월드를 구역(셀)으로 나눠 가까운 곳만 불러옴 → 일반 노트북 성능 확보
4. **성능 예산**: 내장 그래픽 노트북에서 1080p 30fps 이상, 1회 다운로드 크기 목표 관리
5. **저장 데이터 호환**: 버전이 바뀌어도 이전 저장 파일을 불러올 수 있게 변환기 유지

## 4. 폴더 구조 (예정)
```
game/            게임 본체 (TypeScript)
  src/engine/    렌더링, 입력, 물리, 카메라(1·3인칭)
  src/sim/       세계 시뮬레이션 (시간, 경제, 관계, 전투 규칙)
  src/story/     대화·퀘스트·엔딩 실행기
  src/ui/        HUD, 메뉴, 일지
  data/          출신, 아이템, 대사, 퀘스트 (콘텐츠)
  locales/       언어별 번역
  assets/        모델, 텍스처, 사운드 (라이선스 기록 필수)
tools/           자체 제작 도구 (대사 편집·분기 검사기 등)
tests/           자동 테스트
docs/            기획 문서
jarvis/          자비스 운영 (할 일, 보고서, 회고)
archive/         지난 프로젝트 보관
```

## 5. 에셋 라이선스 원칙
- 무료 에셋은 **CC0 또는 상업 이용 가능** 라이선스만 사용, `assets/LICENSES.md`에 출처 기록
- 다른 게임·작품의 그림, 모델, 음악은 사용하지 않음
