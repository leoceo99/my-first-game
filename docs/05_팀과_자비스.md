# 05. 개발팀과 자비스 운영

## 1. 역할 분담

| 역할 | 담당 | 하는 일 |
|---|---|---|
| **디렉터** | 사용자 | 방향 제시, 승인, 피드백 (실무 없음) |
| **자비스 (총괄 PD)** | 메인 Claude 세션 + 야간 자동 작업 | 일정·우선순위, 업무 배분, 결과 검수, 보고, 팀 개선 |
| 스토리 작가 | `.claude/agents/story-writer.md` | 세계관 설정집, 대사, 분기, 엔딩, 복선 관리 |
| 게임 디자이너 | `.claude/agents/game-designer.md` | 시스템 규칙, 수치 밸런스, 조작감, 튜토리얼 설계 |
| 프로그래머 | `.claude/agents/programmer.md` | 엔진·시스템 구현, 성능, 도구 제작 |
| 아트·사운드 디렉터 | `.claude/agents/art-sound-director.md` | 시각 스타일, 에셋 수급·라이선스, 연출, 효과음·음악 |
| QA 테스터 | `.claude/agents/qa-tester.md` | 자동 플레이 테스트, 버그 보고, 스토리 모순·분기 누락 검사 |
| 현지화 담당 | `.claude/agents/localizer.md` | 다국어 번역, 뉘앙스·말투 보존, 용어집 관리 |

> 토큰(사용량) 절약 원칙: 에이전트는 **필요할 때만** 부릅니다. 간단한 작업은 자비스가 직접 처리하고, 큰 작업만 전문 에이전트에게 맡깁니다.

## 2. 업무 흐름

```
디렉터 승인 ─▶ jarvis/TASKS.md (할 일 목록, 우선순위)
                   │
          자비스가 다음 작업 선택 ─▶ 필요 시 전문 에이전트 배정
                   │
          구현·작성 ─▶ QA 자동 테스트 ─▶ 자비스 검수
                   │
          jarvis/reports/ 보고서 + 플레이 링크 ─▶ 디렉터 피드백
                   │
          jarvis/LESSONS.md 회고 기록 ─▶ 규칙·도구 개선 (자비스 성장)
```

## 3. 야간 자동 작업
- **시간**: 매일 새벽 (한국 시간 02:52 시작) 1회
- **범위**: `jarvis/TASKS.md`에서 **"승인됨"** 표시가 있는 작업만 진행. 승인되지 않은 작업은 조사·준비(설계 초안, 자료 조사)까지만
- **반영 방식**: 작업 결과는 자비스 전용 브랜치에 올리고 보고서를 남김 → 디렉터 확인 후 반영 (승인 모드 "가")
- **알림**: 작업이 끝나면 Claude 앱 알림
- **안전 규칙**: 지우기·되돌리기 어려운 작업, 외부 공개, 비용이 드는 작업은 하지 않고 보고서에 "승인 필요"로 남김

## 4. 자비스가 성장하는 방법
솔직하게 말씀드리면, 자비스는 Claude를 기반으로 하므로 모델 자체가 Claude보다 똑똑해지지는 않습니다.
대신 **이 프로젝트에서 일을 더 잘하는 쪽으로** 계속 쌓여 갑니다.

1. **회고 기록** (`jarvis/LESSONS.md`): 실수와 원인, 재발 방지책을 매 작업 후 기록 → 다음 작업 시작 시 반드시 읽음
2. **규칙 갱신** (`CLAUDE.md`): 반복되는 교훈은 팀 규칙으로 승격
3. **도구 축적** (`tools/`): 반복 작업은 자동화 도구로 만듦 (분기 검사기, 번역 검수기, 성능 측정기 등)
4. **테스트 축적**: 고친 버그마다 자동 테스트를 추가해 같은 실수를 막음
5. **역량 점검표** (`jarvis/CAPABILITIES.md`): 할 수 있는 것 / 아직 못하는 것 / 개선 계획을 주기적으로 갱신

## 5. 디렉터(사용자)가 하는 일
- 승인: 보고서 끝의 "승인 필요" 항목에 답하기
- 피드백: 플레이 링크로 해 보고, 화면 녹화나 말로 의견 주기
- 자료 제공: 요청 시 에셋 다운로드(Mixamo 등), 음원 준비
