## 0. 한 줄 요약
대화를 **네 종류의 데이터 파일**로 나눈다.
1. 공통 의도 사전: 모든 장면에서 다시 쓰는 "플레이어 말의 뜻" 60개
2. 인물 카드의 기계용 부분
3. 장면 파일: 흐름과 해석표, 대답 후보
4. 언어별 문장 표

게임은 플레이어가 쓴 말을 의도 하나로 바꾼다. 그 의도에 해당하는 해석표 줄을 따라 분기한다. 대답은 조건에 맞는 후보 중 **이번 삶에서 아직 안 한 것**을 고른다.

## 2. 파일 구성 (제안)
```
game/data/
  flags.json                     플래그 장부: 모든 플래그의 이름·종류·범위·설명
  dialogue/intents.json          공통 의도 사전 (뜻·계열만, 문장 없음)
  characters/C-012.json          인물 카드의 기계용 부분
  dialogue/scenes/o01/y22_library.json   장면 하나 = 파일 하나
game/locales/
  ko/intents.json                의도별 대표 문장(매칭 모델이 비교할 예문)
  ko/scenes/o01/y22_library.json 장면 문장 표 { ID: { text, context } }
  en/…, ja/…                     같은 구조
```
- **장면 구조와 문장을 나눈 이유**: 번역가가 장면 흐름을 건드리지 않고 문장 표만 옮길 수 있다. 장면 파일에는 문장 ID만 둔다.
- 문장 표는 지금 `game/data/strings/ko.json`(T-005)과 **같은 모양**(`text` + `context`)이다. 검사기도 같은 것을 쓴다.
- 인물 카드 원본은 그대로 `docs/lore/인물/*.md`(사람이 읽는 글)에 둔다. 게임이 읽는 칸만 JSON으로 옮긴다. 두 곳이 어긋나면 검사기가 경고한다.

## 3. 각 파일의 모양

### 3-1. 플래그 장부 `flags.json`
게임 상태의 모든 이름을 한 곳에 미리 적는다. 장부에 없는 이름이 장면에 나오면 오타로 보고 검사에서 실패시킨다.
```json
{
  "trust": { "type": "int", "scope": "life", "per": "character", "range": [-3, 3], "desc": "인물별 신뢰. 되감기면 0" },
  "PIECE_O01": { "type": "enum", "values": ["없음", "甲만", "乙만", "맞물림"], "scope": "life", "desc": "의심 설계 5절" },
  "knows.성배행": { "type": "bool", "scope": "meta", "desc": "주인공이 알게 된 진실 조각. 되감겨도 남는다" },
  "SURE": { "type": "list", "scope": "life", "desc": "입으로 단정한 것들" }
}
```
- **범위(scope)가 이 게임의 핵심**이다.
  - `life`: 한 번의 삶. 되감기면 지워진다. NPC의 기억과 관계가 여기 든다.
  - `run`: 한 출신의 세 삶 전체.
  - `meta`: 주인공의 기억. 되감겨도 남는다.
- 그래서 "NPC는 기억 못 하는데 주인공은 안다"를 데이터로 쓸 수 있다.

### 3-2. 공통 의도 사전 `dialogue/intents.json`
```json
[
  { "id": "truth",      "family": "믿는다", "desc": "본 것·아는 것을 그대로 말함" },
  { "id": "lie",        "family": "숨긴다", "desc": "알면서 사실과 다르게 말함" },
  { "id": "deflect",    "family": "숨긴다", "desc": "얼버무림, 화제 돌리기" },
  { "id": "threaten",   "family": "따진다", "desc": "해를 끼치겠다고 겁줌" },
  { "id": "bargain",    "family": "떠본다", "desc": "대가를 요구하거나 거래를 제안" },
  { "id": "ask_back",   "family": "떠본다", "desc": "질문으로 되받기" },
  { "id": "accuse",     "family": "따진다", "desc": "상대를 단정해 몰아붙임 → SURE 기록" }
]
```
- 예문(매칭 모델이 비교하는 대표 문장 수십 개)은 언어마다 `locales/<언어>/intents.json`에 둔다.
- 60개 목록 자체는 T-108 작업이다. 여기서는 모양만 정한다.

### 3-3. 인물 카드 기계용 부분 `characters/C-012.json`
```json
{
  "id": "C-012",
  "binding": "명부",
  "voice": ["짧은 문장", "존대→반말 전환 빠름"],
  "neverIntents": ["flatter_back"],
  "confusablePairs": [["pity", "insult"]],
  "familyBias": { "믿는다": "의심", "따진다": "굴복", "떠본다": "역이용", "숨긴다": "눈치챔" },
  "doc": "docs/lore/인물/C-012_….md"
}
```
- `binding`이 `없음`이 아니면 엔진이 그 장면에서 오간 말을 "대악마가 들은 것" 기록에 남긴다(R10).

### 3-4. 장면 파일 `dialogue/scenes/<출신>/<장면>.json` (핵심)
예시는 우리가 지어낸 일반 장면이다(마을 장로가 "어젯밤 무엇을 보았나?" 묻기, docs/08 1절).
```json
{
  "id": "scene.o01.y03_elder",
  "tier": "normal",
  "when": "life >= 1 && era == '유년'",
  "cast": ["C-031"],
  "start": "q1",
  "nodes": {
    "q1": {
      "say": [
        { "line": "scene.o01.y03_elder.c031_01", "when": "trust(C-031) <= 0" },
        { "line": "scene.o01.y03_elder.c031_02", "when": "trust(C-031) > 0" },
        { "line": "scene.o01.y03_elder.c031_03", "when": "knows('장로의아들')", "repeatAcrossLives": true }
      ],
      "ask": {
        "intents": "common50 + ['name_son']",
        "byFamily": {
          "믿는다": { "go": "r_open",  "do": ["trust(C-031) += 1"] },
          "따진다": { "go": "r_close", "do": ["trust(C-031) -= 1"] },
          "떠본다": { "go": "r_wary" },
          "숨긴다": { "go": "r_wary",  "do": ["trust(C-031) -= 1"] }
        },
        "byIntent": {
          "bargain":  { "go": "r_coin" },
          "name_son": { "go": "r_son", "do": ["set PIECE_O01 = '甲만'"], "when": "knows('장로의아들')" }
        },
        "unclear": { "say": ["scene.o01.y03_elder.c031_q1_again"], "then": "default:r_wary" },
        "replies": {
          "truth":    ["…c031_rt_01", "…c031_rt_02"],
          "lie":      ["…c031_rl_01"],
          "threaten": ["…c031_rth_01", "…c031_rth_02"]
        }
      }
    },
    "r_open":  { "say": [{ "line": "…c031_10" }], "go": "end" },
    "r_coin":  { "say": [{ "line": "…c031_20" }], "go": "end" },
    "end":     { "end": true }
  }
}
```
읽는 법:
- **`byFamily`가 기본 규칙**이고 `byIntent`가 예외다. docs/08의 "기본 규칙 + 예외"와 같다.
  - 의도 60개를 일일이 연결하지 않아도 4줄로 모든 의도가 어딘가로 간다.
  - 덕분에 작가는 꼭 다르게 가야 하는 의도만 따로 쓴다.
- **`replies`는 분기와 따로** 의도마다 NPC의 첫 반응 문장 후보를 둔다. 같은 분기로 가도 반응 문장은 의도마다 다르다(디렉터 결정 11-13). 비어 있는 의도는 계열 기본 반응 문장을 쓴다.
- 대답 고르기 순서:
  1. `when`이 맞는 후보만 남긴다.
  2. 이번 삶에서 이미 한 줄은 뺀다. 단 `repeatAcrossLives`는 세 삶 반복 대사라서 삶마다 한 번 허용한다.
  3. 남은 것 중 가장 구체적인 조건을 가진 줄을 고른다.
  4. 아무것도 안 남으면 그 인물의 "말 없음" 반응(침묵·몸짓)을 쓴다.
- `"말 고르기"` 선택지는 따로 쓰지 않는다. 각 의도의 **대표 문장 1개**를 그대로 버튼 글로 쓴다. 그래서 모델 없이도 같은 해석표로 진행된다(요구 8).

### 3-5. 조건·효과 식 (작은 규칙 언어)
- 형식: `trust(C-031) > 0 && knows('장로의아들') && life == 2` 같은 **짧은 글자 식**. 엔딩 표기(`GODS≥7`, `KINGS=0`)와 비슷하게 읽힌다.
- 쓸 수 있는 것은 플래그 장부의 이름, 비교, `&&`·`||`·`!`, 숫자·문자열뿐이다.
- 함수 호출이나 반복은 없다. 그래서 검사기가 모든 식을 미리 해석해 오타·없는 플래그·범위 밖 값을 잡을 수 있다.
- 효과: `set X = v`, `trust(C) += n`, `add SURE '범인=○○'`, `goto 장면ID`.

### 3-6. 문장 표 `locales/ko/scenes/…json`
```json
{
  "scene.o01.y03_elder.c031_01": {
    "text": "어젯밤… 네 녀석, 우물가에 있었지.",
    "context": "장로→주인공(아이) · 신뢰 낮음 · 의심 · 복선 아님 · 짧게 끊는 말투"
  }
}
```
ID 규칙은 인물 양식 139줄의 `scene.<출신>.<장면>.<인물>_<번호>`를 따른다.

## 4. 실행 흐름 (게임 안에서)
```
플레이어 입력 → (기기 안 매칭 모델) 의도별 점수
  → 이 장면이 허용한 의도만 남김 → 1등 점수가 기준 미만? → unclear(되묻기, 두 번째면 기본 반응)
  → byIntent 있으면 그쪽, 없으면 byFamily → 효과 적용 → replies에서 첫 반응 → 다음 노드
  → 기록: FAMILY_OK/FAIL, 묶인 사람이 있으면 '대악마가 들은 말'
```
- 판정 숫자(신뢰, 플래그)는 **게임 규칙**이 바꾼다. 문장을 고르는 일만 데이터가 한다. AI 실시간 대답을 나중에 붙여도 규칙은 그대로다(docs/08 1절).

## 5. 검사기로 잡을 것 (T-008과 연결)
| 검사 | 실패 예 |
|---|---|
| 도달 불가 노드·문장 | `r_son`으로 가는 길이 조건상 영원히 거짓 |
| 장부에 없는 플래그·인물 | `trust(C-03l)` 오타 |
| 허용 의도가 갈 곳 없음 | `byFamily`에 계열 하나가 빠짐 |
| 반복 금지 위반 위험 | 한 삶에서 두 번 올 수 있는 노드인데 후보 문장이 1개뿐이고 `once`도 아님 |
| 맥락 메모 없음, 언어별 문장 누락, UI 길이 초과 | docs/06 |
| 출신마다 해피엔딩 정확히 1개, `[규칙 파괴]` 1개 | 엔딩도감 v1.1 자동 검사 규칙 |
| 4계열이 한 출신에서 5장면 넘게 연속 정답/오답 | 의심 설계 5절 |

## 6. 바깥 도구(ink)와 비교 — 지식 기반, 웹 조사 안 함
| | 우리 JSON 형식 | ink (공개된 대화 스크립트 언어, MIT 허가) |
|---|---|---|
| 의도 해석표(계열 기본+예외) | 그대로 표현 | 선택지 중심이라 60개 의도 표를 쓰기 어색함 |
| 문장 ID·맥락 메모·번역 | 문장 표 분리라 자연스러움 | 대본 안에 문장이 섞여 ID·메모를 따로 붙여야 함 |
| 작가가 읽기 쉬움 | JSON은 다소 딱딱함 | 매우 읽기 쉬움 |
| 검사기 | 우리가 만들어야 함 | 기본 검사 도구가 있음 |

→ **추천: 우리 형식.** 의도 매칭과 문장 ID가 이 게임의 중심이라 ink의 장점(줄글 대본)이 덜 산다. 작가 편의는 나중에 "장면 보기" 도구(표 형태로 보여 주기)로 보완한다.

## 7. 크기 어림 (확인 전 추정)
- 장면 1개(의도 50~60개, 대답 1~2개씩, 문장 평균 40자)는 한 언어에 약 4~8KB다.
- 장면 3,000개면 한 언어 12~24MB다. 구역 단위로 나눠 불러오면(docs/03 3장 3) 한 번에 받는 양은 작다.

## 8. 결정 필요 (디렉터 · 번호, 추천 포함)
1. **조건 표기**를 짧은 글자 식(`trust(C) > 0 && …`)으로 할까, JSON 구조로 할까?
   - 추천: 글자 식 + 검사기. 엔딩 표기와 비슷해 작가가 읽기 쉽다.
2. **NPC 대답이 이전 삶을 기억하게** 할까? NPC는 되감기로 잊지만, 주인공이 아는 것(`meta` 범위)에 따라 대답 후보를 바꾸는 것은 허용할까?
   - 추천: 허용. 주인공이 "알 수 없는 것을 아는" 순간의 반응(인물 양식 6절)이 이것으로 표현된다.
3. **의도별 첫 반응 문장**(`replies`)을 모든 장면에서 50~60개 다 쓸까, 중요 장면만 다 쓰고 일반 장면은 계열 기본 반응(4개)+일부 예외로 둘까?
   - 추천: 디렉터 결정(최대한 모든 장면)을 지키되, **작업 순서**는 중요 장면부터. 일반 장면은 AI 초안을 대량으로 뽑은 뒤 작가가 검수한다(docs/08 작업량 관리).
4. 이 초안으로 **예시 장면 1개 + 최소 검사기**를 만들어 볼까? (T-008 일부)
   - 추천: 예. 장면 하나를 실제로 프로토타입에서 돌려 보면 형식의 빈틈이 빨리 보인다.
